# 竞品日报编辑规范

2026-10-27 修订。目标是可在几分钟内读完的主题简报，而非采集台账。

用户指定参考 https://aihot.news/daily 。当前访问返回 403，浏览器权限关闭，因此本版不声称已复刻其布局或栏目。

## 两层产物

- 证据层：原始响应、SQLite、全量采集 JSON、每日采集附录；保留原文与来源，不删改历史证据。
- 日报层：3 条以内导读、通常 3–6 个主题。围绕事实/反馈、对目标用户的意义、验证边界与后续观察来组织。
- 用户只说“好”“垃圾”且无场景的短评不进正文。跨媒体报道合并为一件事；不是按产品凑满 9 段。
- 发布日与发现日分开；历史补录不写成今天发布。采集成功但零样本不代表没有动态。
- 新闻标题不够支持功能结论时，只作待核验短讯；没有客户部署证据就不填客户章节。
- GitHub issue 是提交者报告，区分功能请求/源码复现/线上问题/维护者确认/修复发布。
- 口碑按产品和任务聚合，兼顾正反例，不按星级替代正文，不估计总体满意度。

## 自动运行

1. collect.py 采集并输出原始台账、日报候选包和未编辑时的简洁预览。
2. Codex 自动化阅读候选包及必要原始证据，编辑 monitor/editorials/YYYY-MM-DD.json。
3. python3 monitor/digest.py --date YYYY-MM-DD 渲染并验证来源 ID、引文、日期、数量限制。
4. 未完成编辑时明确显示“自动候选稿”，不让规则摘录冒充已编辑日报。已有编辑稿在重新采集后保持不覆盖。

编辑由当前 Codex 会话完成，不需要独立 AI API；这不等于有一个脱离 Codex 的自主模型后端。模型费用和执行条件仍受 Codex 环境约束。周/月报暂保持原汇总机制，本轮只重做日报。

## 数据格式

以 monitor/editorials/2026-10-27.json 为示例。每个主题包含 id、section、product、badge、title、summary、observations、meaning、next、limits、evidence_ids 和 quotes。每条引文必须是所引用记录 excerpt 的原文子串；source ID 必须存在且在当期发现截止范围内。日期、版本等论断仍需编辑者核对，结构校验不能替代事实核验。
